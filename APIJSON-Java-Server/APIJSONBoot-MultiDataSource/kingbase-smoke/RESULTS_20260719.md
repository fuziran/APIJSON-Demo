## Confirmed SQL Server difference and fix

The real SQL Server-compatible instance established behavior that proxy JDBC tests did not expose:

1. The valid identity DDL is `BIGINT IDENTITY(1,1)`, not
   `GENERATED BY DEFAULT AS IDENTITY`.
2. An identity INSERT returns `-1` from `getUpdateCount()`.
3. Both generated-column-name and `RETURN_GENERATED_KEYS` preparation followed by
   `executeUpdate()`/`getGeneratedKeys()` fail with SQLState `02000`.
4. `PreparedStatement.execute()` returns `true`; `getResultSet()` contains one
   `GENERATED_KEYS` column with JDBC type `NUMERIC`, Java type `BigDecimal`, and the identity value.

`AbstractSQLExecutor.executeUpdate(...)` now follows that result-set path only for an auto-generated
`KINGBASE-SQLSERVER` POST, sets the APIJSON id, and reports one affected row. MySQL and Oracle keep
their existing `getGeneratedKeys()` behavior.
